Open decisions

A. Video frame extraction vs burst capture

Video can guarantee overlap from frame rate without computing angles; the cost is rolling shutter while moving and per-frame quality.

Recommendation: start with burst + Loop A. The 38 ms shutter is known-sharp when stopped; video is continuous motion, with unknown risk and too many variables changing at once.

B. Route strategy: random bounce vs intentional path

Current behavior is Roomba-style random; coverage is probabilistic. Published autonomous capture systems all use map-based navigation.

Recommendation: leave it. Wait until Loop A is live and the first connected model appears, then decide whether a wall-follow loop + center sweep is needed.

C. What overlap threshold to use

Today's data: lowest same-model adjacent pair is 19 matches; highest different-model pair is 25 — the ranges overlap, so this cannot predict connectivity. The reverse (as a sufficient condition) does hold.

Recommendation: set the threshold in the clearly-connected range (~200). Use it as a live "is overlap enough" gate, not as a "will the model split" predictor. Calibrate after field runs with --keep-rejected.

D. Auto-trigger COLMAP vs manual

Could watch incoming/ and auto-run, or keep it manual.

Recommendation: keep it manual. Each round still needs a human reading the overlap matrix; automation would only add a layer nobody looks at.

Suggested implementation order

Do not start this sequence until four obstacle sensors are installed. The order below is the plan to resume with, not work to do now.

  1. Capture while turning — close the current station-to-station gaps (smallest change, largest expected gain)
  2. Loop A overlap gate — use existing repeatable_keypoints()
  3. Burst step 20° → 15°
  4. Stage 2 rsync + manifest
  5. Stage 4 scale anchoring

Items 1–3 can be combined into one supervised field run, with --keep-rejected enabled to finish threshold calibration.
